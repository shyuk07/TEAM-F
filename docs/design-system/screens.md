와이어프레임 원본에서 화면마다 뽑은 명세입니다. 각 화면은 **ID · 제목 · API · 역할 · 쓰는 컴포넌트 · 화면 문구 · 연결 화면 · 동작 메모** 순서입니다. 메모의 **확인 필요**·**백엔드 필요**는 아직 정해지지 않은 항목이며 `open-issues.md`에 모아 두었습니다.

## 공통 · 로그인·계정 (모든 역할)

### A1 · 로그인

- API: `POST /v1/auth/login {email, password}`
- 역할: 고객, 상점주, 관리자
- 컴포넌트: AppBar, CtaBar, Button, Input, FieldError
- 버튼: 「로그인」 / 「회원가입」
- 입력 라벨: 「이메일」 / 「비밀번호」
- 텍스트 링크: 「비밀번호 재설정」 / 「사장님이신가요? 입점 신청」
- 오류·경고 문구: 「이메일 또는 비밀번호가 올바르지 않습니다.」
- 연결 화면: C2, C1, O0, O1, M1

동작 메모:

- 제목은 "로그인" 고정, 들어온 경로에 따라 아래 한 줄만 바뀜: C2 → "예약을 이어가려면…", 내 예약·마이 탭 → "예약 내역을 보려면…", 홈 상단 링크 → 문구 없음.
- 역할 선택 없음. 로그인 뒤 계정 역할로 이동: 고객은 원래 보던 화면(또는 C1), 상점주는 O0/O1, 관리자는 M1.
- 상점주·관리자는 홈 상단 "로그인"으로 들어옴.

### A2 · 회원가입

- API: `POST /v1/auth/signup {email, password, name, phone, role}`
- 역할: 고객, 상점주
- 컴포넌트: AppBar, CtaBar, Button, Input, FieldError, RolePicker
- 버튼: 「가입하기」
- 입력 라벨: 「어떻게 이용하시나요? *」 / 「이름 *」 / 「이메일 *」 / 「비밀번호 * (8자 이상)」 / 「전화번호 *」
- 오류·경고 문구: 「이미 가입된 이메일입니다.」
- 연결 화면: O0

동작 메모:

- 역할은 여기서만 고름. 상점주를 고르면 "이름" 라벨이 "상호(상점명으로 쓰임)"로 바뀜.
- 가입 응답에는 토큰이 없으므로 성공 후 같은 이메일·비밀번호로 로그인 API를 바로 호출.
- 가입 후 이동은 A1과 같음: 고객은 가입 전에 있던 화면으로(C2에서 왔으면 같은 수량으로 예약 이어가기), 상점주는 O0(승인 대기).

### A3 · 비밀번호 재설정

- API: `POST /v1/auth/password-reset/request · /confirm`
- 역할: 고객, 상점주, 관리자
- 컴포넌트: AppBar, CtaBar, Button, Input, FieldError, Box
- 버튼: 「코드 보내기」 / 「비밀번호 바꾸기」
- 입력 라벨: 「1단계 · 코드 받기」 / 「가입한 이메일」 / 「2단계 · 새 비밀번호」 / 「6자리 코드」 / 「새 비밀번호 (8자 이상)」
- 텍스트 링크: 「코드 다시 받기」
- 오류·경고 문구: 「코드가 맞지 않거나 만료됐어요. 코드를 다시 받아 주세요.」
- 연결 화면: A1

동작 메모:

- A1 "비밀번호 재설정"에서 들어옴. 1단계를 보내면 2단계가 열림. 완료 후 A1로, "새 비밀번호로 로그인하세요".
- 가입 여부와 상관없이 같은 안내(204)로 이메일 존재 여부를 드러내지 않음. 코드 오류·만료·횟수 초과는 모두 같은 오류 문구(INVALID_RESET_CODE).
- 현재 코드는 서버 로그로만 남고 이메일로 보내지 않음(reset_notifier.py) → 메일 발송 **확인 필요**.

### C5 · 내 예약

- API: `GET /v1/users/me/reservations`
- 역할: 고객
- 컴포넌트: AppBar, TabBar, Chip, StatusTag, Button, Box, PickupCode
- 하단 탭: 홈 내 예약 마이 (굵은 항목이 현재 탭)

- 칩: 「진행 중」 / 「지난 예약」
- 상태 태그: 「예약 확정」 / 「매장 사정으로 취소됨」 / 「결제 대기」 / 「픽업 시간 지남」
- 입력 라벨: 「매장에서 보여 주세요」
- 텍스트 링크: 「예약 취소 · 17:00까지」
- 연결 화면: O1, C5a, E1

동작 메모:

- 코드 카드에 예약 시각(17:42 예약)을 함께 표시 → 상점주 O1 목록의 예약 시각과 바로 맞춰 볼 수 있음(백엔드 변경 없음).
- 매장 사정으로 취소된 예약(점주의 판매 중단, cancelled_by=STORE)은 — 관리자의 할인 정지·강제 폐점은 예약을 취소하지 않고 새 예약만 막음 — 원래 픽업 종료 시각까지 "진행 중" 탭에 남겨 둠. 알림 기능이 없어 고객이 앱을 열어야만 알 수 있음.
- 확정 예약의 취소는 길찾기와 떨어진 오른쪽 텍스트 링크 → C5a 확인. 링크에 마감 시각을 함께 표시.
- 취소 마감(픽업 시작 − 1시간)이 지나면 링크 대신 회색 문구 "취소 마감 지남 (17:00)", 누를 수 없음(E1 참고). 현재 백엔드 cancel()은 마감 시각을 검사하지 않음 → 서버 규칙 추가 **확인 필요**.
- 취소 구분은 예약 응답의 **cancelled_by**로 표시(**백엔드 반영됨 #44**, 내 예약 목록과 취소 응답에 들어감): CUSTOMER → "직접 취소", STORE → "매장 사정으로 취소됨", 그 외·null → "취소됨". SYSTEM(탈퇴 회원 예약)은 고객 화면에 나오지 않음.
- 미수령(노쇼): 픽업 종료 후에도 DB 상태는 "예약 확정"으로 남음 → "픽업 시간 지남"은 DB 상태가 아니라 화면이 계산해 표시(예약 확정 상태 + pickup_end가 지남). 환불·상태 전이 규칙은 백엔드에서 정해야 함(**확인 필요**).

- O2 "재고 조정"에서 열림(PC는 O2 우측 패널). 0은 보낼 수 없음 → 스텝퍼 최소 1. 0개가 되면 자동으로 품절.

### O11 · 상품 수정 · 숨기기

- API: `PATCH /v1/products/{id} · /deactivate · /activate`
- 역할: 상점주
- 컴포넌트: AppBar, TopNav, CtaBar, Chip, Button, Input, Box, PhotoSlot, AccountButton, SplitLayout
- 버튼: 「사진 바꾸기」 / 「저장」

- 텍스트 링크: 「사진 삭제」 / 「숨기기」
- 연결 화면: O4, O12

동작 메모:

- O4 상품 행을 누르면 열림. 숨김 상품은 "다시 보이기" 버튼으로 바뀜.
- 숨길 때 진행 중 할인·예약이 어떻게 되는지 API 규칙 확인 후 확인 단계 추가(**확인 필요**).
- 사진 바꾸기 → O12 흐름. 사진 삭제는 바로 지우지 않고 저장할 때 반영.

### O12 · 상품 사진 올리기 (1장)

- API: `POST /v1/products/{id}/images → products.product_image`
- 역할: 상점주
- 컴포넌트: AppBar, BottomSheet, Button, FieldError, PhotoSlot, SplitLayout
- 버튼: 「카메라로 찍기」 / 「앨범에서 고르기」 / 「사진 바꾸기」 / 「다시 시도」 / 「다른 사진 고르기」
- 입력 라벨: 「① 사진 고르기」 / 「② 업로드 중」 / 「③ 올라감」 / 「④ 실패」
- 텍스트 링크: 「취소」 / 「삭제」
- 오류·경고 문구: 「사진이 5MB보다 커요. 더 작은 사진을 골라 주세요.」

동작 메모:

- **규칙: 상품당 사진 1장.** 이미 있으면 "추가" 대신 "바꾸기"만 보임. 새 사진이 다 올라간 뒤에 예전 사진과 바뀜(실패해도 예전 사진 유지).
- 화면에서 4:3으로 미리 보여 주고, 고객 카드·상세에서도 같은 비율로 자름.
- **DB:** products.product_image(JSON 목록) 그대로 씀 → 사진 있음 ["url"], 없음 null 또는 []. 컬럼 변경 불필요.
- **백엔드 반영됨 #42:** ① 업로드 **POST /v1/products/{id}/images**(201), 삭제 DELETE /v1/products/{id}/images/{image_id}(204), 조회 GET …/images/{image_id}(공개). JPEG·PNG·WebP(파일 내용으로 판별), **5MB 이하**, DB 저장. 올린 이미지 주소가 products.product_image 목록에 들어감(상품 응답 형식 불변). ② 백엔드는 상품당 최대 10개(외부 URL 포함)까지 받으므로, "1장" 규칙은 화면에서만 지킴(백엔드에서도 막을지는 **확인 필요**). ③ 사진을 바꿀 때는 새 사진 업로드 후 예전 사진 DELETE.

동작 메모:

### M3 · 회원 탭 · 회원 상세

- API: `GET /v1/admin/users · /users/{id} · /users/{id}/points`
- 역할: 관리자
- 컴포넌트: AppBar, TabBar, TopNav, TableRow, Chip, StatusTag, Button, Input, KeyValue, Box, AccountButton, SplitLayout
- 하단 탭: 승인 회원 상점 할인 (굵은 항목이 현재 탭)
- 버튼: 「이전」 / 「다음」 / 「포인트 지급 (M4)」 / 「정지 (M2)」

- 입력 라벨: 「이름 · 이메일」 / 「역할」 / 「가입일」 / 「상태」 / 「최근 포인트 내역」
- 텍스트 링크: 「강제 탈퇴」

동작 메모:

- 목록은 **GET /v1/admin/users**(관리자 전용, **백엔드 반영됨 #42**, 명세 admin.md 10절). 쿼리: role(CUSTOMER/OWNER/ADMIN), status(PENDING/APPROVED/REJECTED/SUSPENDED/WITHDRAWN; 정지 기간이 지난 회원은 APPROVED로 취급), email(부분 검색, 대소문자 무시), page(**1부터**), size(1~100, 기본 20; 범위 밖이면 400 INVALID_PAGE). 응답 {items:[{id, email, name, role, status, created_at}], page, size, total}. 정렬은 가입 오래된 순(오래 기다린 회원 먼저). 전화번호·포인트는 목록에 없으므로 단건 조회(GET /v1/admin/users/{id})로 본다. 상태 필터를 비우면("전체") 탈퇴 회원도 포함.
