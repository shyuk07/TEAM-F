# 미결 사항

메모에서 **확인 필요**, **백엔드 필요**, **팀 결정 필요**, **백엔드 반영 중**이 붙은 항목입니다. 정해지기 전까지는 각 항목에 적힌 임시 동작대로 구현하고, 빈칸을 임의로 채우지 마세요.

- **A3** (비밀번호 재설정): 현재 코드는 서버 로그로만 남고 이메일로 보내지 않음(reset_notifier.py) → 메일 발송 **확인 필요**.
- **C8** (프로필 변경): 상점주는 "상호" 칸을 잠금: 상점은 개설할 때 이름을 복사해 두므로, 바꾸면 계정 이름과 상점명이 달라짐. 상호 변경 규칙이 정해질 때까지 전화번호만 수정(**확인 필요**).
- **O8** (계정 메뉴): 상점주 회원 탈퇴는 API가 있지만(POST /users/me/withdraw) 상점·예약 처리 규칙이 없어 메뉴에서 뺌 → **확인 필요**.
- **C1a** (위치 · 반경): 주소를 입력해 위치를 바꾸려면 주소 → 좌표 변환이 고객용으로 필요(상점 개설용 카카오 변환만 있음) → **확인 필요**. 그 전까지는 현재 위치만.
- **C4** (결제 완료): 코드가 결제 응답에 오는지, 예약 조회로 다시 받아야 하는지 **확인 필요**(이슈 18).
- **C5** (내 예약): 취소 마감(픽업 시작 − 1시간)이 지나면 링크 대신 회색 문구 "취소 마감 지남 (17:00)", 누를 수 없음(E1 참고). 현재 백엔드 cancel()은 마감 시각을 검사하지 않음 → 서버 규칙 추가 **확인 필요**.
- **C5** (내 예약): 미수령(노쇼): 픽업 종료 후에도 DB 상태는 "예약 확정"으로 남음 → "픽업 시간 지남"은 DB 상태가 아니라 화면이 계산해 표시(예약 확정 상태 + pickup_end가 지남). 환불·상태 전이 규칙은 백엔드에서 정해야 함(**확인 필요**).
- **C5b** (내 예약 · 지난 예약): 취소 카드의 "직접 취소"·"매장 사정으로 취소됨"·"취소됨" 구분은 cancelled_by(C5 참고, **백엔드 반영됨 #44**). "픽업 시간 지남"은 DB 상태가 아니라 화면 계산(예약 확정 + pickup_end 지남), 노쇼 환불 규칙은 미결정.
- **O1** (오늘 · 픽업 처리): **백엔드 필요:** 상점주 목록 항목에 픽업 시간(pickup_start·pickup_end)이 없음 → 추가 필요. 고객 정보·픽업 코드는 R-REQ25로 계속 빼 둠.
- **O1** (오늘 · 픽업 처리): **백엔드 필요:** 지금 픽업 API는 예약 ID가 필요함(POST /reservations/{id}/pickup) → 행을 고르지 않으므로 코드만으로 예약을 찾아 픽업 처리하는 API(상점 범위 안에서 코드 조회) 필요(**확인 필요**).
- **O5** (판매 중단 확인): 백엔드에 푸시·문자·이메일 알림이 없어 "고객에게 알림" 약속을 뺌. 알림 기능 추가는 **확인 필요**. 관리자 할인 정지·강제 폐점도 같음.
- **O11** (상품 수정 · 숨기기): 숨길 때 진행 중 할인·예약이 어떻게 되는지 API 규칙 확인 후 확인 단계 추가(**확인 필요**).
- **O12** (상품 사진 올리기 (1장)): **백엔드 반영됨 #42:** ① 업로드 **POST /v1/products/{id}/images**(201), 삭제 DELETE /v1/products/{id}/images/{image_id}(204), 조회 GET …/images/{image_id}(공개). JPEG·PNG·WebP(파일 내용으로 판별), **5MB 이하**, DB 저장. 올린 이미지 주소가 products.product_image 목록에 들어감(상품 응답 형식 불변). ② 백엔드는 상품당 최대 10개(외부 URL 포함)까지 받으므로, "1장" 규칙은 화면에서만 지킴(백엔드에서도 막을지는 **확인 필요**). ③ 사진을 바꿀 때는 새 사진 업로드 후 예전 사진 DELETE.
- **M1** (승인 · 회원 · 상점 관리): 상점 탭·할인 탭의 목록 API는 아직 없음 → **확인 필요**. 그 전까지 상점 정지·폐점은 상점 ID를 알아야 함.
