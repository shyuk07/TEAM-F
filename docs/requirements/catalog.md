# catalog 도메인 요구 조건 — 상품

상태: 검토 중 (8회차)
입력: `docs/design/catalog.md` §3.3·§6 #1·#5·#6·D6·D7·D9·D13·D16·D17, `src/catalog/domain/product.py`, 이 문서의 이전 확정본(2026-11-04)과 사용자 답변(1~2회차)
표시: [입력] 근거 있음 / [판단] 작성자 판단, 판단 메모 참조 / [제안] 작성자 제안, 확인 필요 / [기입 필요] 사용자 기입

> 기입 방법: 맨 아래 "검토 요청"의 각 `사용자:` 아래에 자유롭게 답을 쓴 뒤 재검토를 요청한다. 본문을 직접 고쳐도 된다.

## 범위

- 포함: 상품 하나의 등록·수정·노출 중단·재노출·조회 규칙
- 제외: 할인 상품 자체의 규칙, 상점 폐점이 상품에 미치는 처리. 상품 규칙이 할인 상품이나 상점 상태를 **조건으로만** 참조하는 경우는 포함한다.
- 제외된 결정의 위치: 아래 "범위 밖으로 옮긴 항목"

## 불변식
- REQ-1. 상품은 반드시 한 상점에 속하며, 소속 상점은 바뀌지 않는다. [입력] product.py:12, :18
- REQ-2. 상품명은 앞뒤 공백을 뺀 뒤 1자 이상 200자 이하이며, 항상 있어야 한다. [입력] design §3.3, D16
- REQ-3. 정상 가격은 1 이상 2,147,483,647 이하의 정수이며, 항상 있어야 한다. 범위를 넘는 값은 입력 오류로 거부한다. [입력] design §3.3, D16, 사용자 답변(8회차)
- REQ-4. 카테고리는 없을 수 있다. 있으면 앞뒤 공백을 뺀 뒤 1자 이상 80자 이하의 자유 입력 문자열이다. [입력] design §3.3, 이전 확정본 RQ-10
- REQ-5. 설명은 없을 수 있으며, 길이 상한은 없다. [입력] design §3.3, 이전 확정본 RQ-4
- REQ-6. 상품 이미지는 0개 이상 10개 이하이며, 각 이미지 주소는 공백일 수 없다. 이미지 목록 자체는 항상 있다(비어 있을 수 있음). [입력] design §3.3, D16
- REQ-7. 새로 등록된 상품은 노출 중 상태이다. [입력] design §3.3 `register`
- REQ-8. 진행 중인 할인 상품이 있으면, 상품의 정상 가격은 그 할인 가격보다 커야 한다. [입력] design §3.3 `apply_changes`
- REQ-9. 노출 중단된 상품에는 할인 상품을 등록할 수 없다. [입력] design §3.3 `ensure_active_for_offer`
- REQ-10. 상품 수정은 여러 항목을 한 번에 바꿀 때 모두 규칙을 지키는 경우에만 반영되고, 하나라도 어기면 아무것도 바뀌지 않는다. 바꿀 항목이 하나도 없으면 수정이 성립하지 않는다. [입력] design §3.3 `apply_changes`

사용자: Integer 한계를 넘으면 입력 오류 처리로 결정해.
반영: REQ-3, 경계값 "정상 가격" (8회차)

반영: 본문 값 변경 없음. 표시 범례에 `[판단]`을 추가하고 빈 "판단 메모" 절을 만듦. 새 규칙에서 질문 대상이 되는 미결 결정은 없음.

### RQ-13. 노출 중단 상품과 폐점 상점의 상품을 계속 수정할 수 있게 할까요?
대상: 주체와 정책 "상품 수정"
배경: 설계는 이 두 경우의 수정을 허용하되 "임시" 결정으로 두었습니다(design D17). 폐점 상점의 상품은 재노출할 수 없게 되었으므로(이전 확정본 RQ-11) 수정만 허용하는 것이 맞는지 확인이 필요합니다.
제안: 둘 다 허용(설계 D17 유지) — 근거: 수정은 노출 여부를 바꾸지 않으므로 다른 규칙과 충돌하지 않는다.

사용자: 폐점의 의미를 확인해야해. 패점이란? 사용자가 더이상 상점운영을 중지하는 것으로 계정은 활성화되어있더라도 해당 상점은 접근할수없다라는 기준이라면 수 검색, 수정 모두 되어선 안돼.
작성자: 명세의 폐점은 "상점주가 본인 상점의 운영을 멈추는 것"이며, 폐점한 상점은 **재개점할 수 있습니다**(`docs/reference/stores.md:74-79`). 폐점 후 막히는 것은 상품·할인 등록뿐이고, 상점 접근 차단은 정해져 있지 않습니다. 재개점이 가능하므로 상점주가 상품을 완전히 못 보게 하면 재개점 후 관리가 어렵습니다.
제안: 폐점 상점의 상품은 일반 사용자의 조회·검색에서 제외하고, 상점주는 조회·수정할 수 있다. 재노출만 막는다(RQ-11). — 근거: 재개점 가능(stores.md:79), 노출 중단 상품 조회 규칙(RQ-8)과 같은 방식
폐점을 "재개점 없는 영구 종료"로 바꾸려면 그렇게 적어 주세요. 그 경우 상점주도 조회·수정 불가로 반영합니다.
사용자: 너의 제안으로 결정. 페점 상태에 상품 노출은 불가능
반영: 주체와 정책 "상품 수정"·"노출 중 상품 조회"·"폐점 상점의 상품 조회", 소멸 절 (6회차)

### RQ-12. 재노출 규칙이 설계의 "재노출 없음" 결정과 충돌합니다. 요구 조건을 따를까요?
대상: 주체와 정책 "재노출", 상태와 전이
배경: 이 문서의 이전 확정본은 재노출을 허용했지만(RQ-7), 설계는 "재노출 기능을 만들지 않는다"를 확정으로 두고 있습니다(design D13). 두 기준 문서가 서로 다르므로 어느 쪽인지 정해야 합니다.
제안: 요구 조건을 따른다. 재노출은 노출 중단과 같은 주체·조건으로 허용한다(상점주, 본인 상점, 상점 미폐점). 이미 노출 중이면 거부한다. 설계 D13은 이후 설계 단계에서 고친다 — 근거: 이전 확정본이 D13보다 나중의 사용자 결정이고, 노출 중단(design §6 #6)과 대칭이 된다.
