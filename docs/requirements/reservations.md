### RQ-17. 픽업 시간이 지난 예약은 어떻게 처리하나요?
대상: REQ-22, 주체와 정책 / 픽업 완료
배경: Catalog 확정 D54의 고객 안내 문구는 "픽업 시간 안에 매장을 방문해 예약 확인 코드를 보여주세요. 픽업 시간이 지나면 수령할 수 없습니다"입니다(main `23c67c3` `docs/design/catalog.md:783`, `docs/reference/catalog.md:498`). 이것은 고객에게 보여 주는 확정 문구이며, 픽업 완료 처리를 실제로 막는 규칙이나 마감 이후 예약의 처리는 Catalog 문서에 없습니다. 상품 인도와 돈에 관한 결정이라 작성자가 정하지 않습니다.
제안: 정하지 않고 묻습니다. 함께 정해야 할 것: ① 픽업 마감 이후 픽업 완료를 막는가 ② 픽업 시작 전 픽업 완료도 막는가("픽업 시간 안에") ③ 마감까지 찾아가지 않은 예약 확정 예약은 어떤 상태가 되고 환불하는가(그대로 둠 / 자동 취소·환불 / 위약금). 현재 구현은 시간과 무관하게 픽업 완료를 허용합니다(`rules.py` `PICKUP_WINDOW_ENFORCED = False`).


사용자: (2026-11-06, 대화로 받은 답변, 사용자 승인) 1. 픽업은 예약 확정(RESERVED) 상태에서만 가능합니다. 2. 픽업 가능 시간은 Catalog에서 정한 pickup_start부터 pickup_end까지입니다. 3. 픽업 시작 시각과 정확히 같은 시각에는 픽업을 허용합니다. 4. 픽업 마감 시각과 정확히 같은 시각에도 픽업을 허용합니다. 5. 픽업 시작 전에는 픽업 완료를 허용하지 않습니다. 6. 픽업 마감 이후에는 픽업 완료를 허용하지 않습니다. 7. 결제 대기, 취소, 이미 픽업 완료된 예약은 기존 규칙대로 픽업 완료할 수 없습니다. 8. 픽업 마감 이후 상품을 찾아가지 않은 결제 완료 예약의 최종 상태 및 환불 처리는 아직 확정하지 않습니다. 9. 자동 취소, 자동 환불, 새로운 예약 상태를 임의로 도입하지 않습니다. 10. 미확정된 마감 이후 처리 정책은 별도 질문으로 유지합니다.
작성자(재검토 13회차, 2026-11-06): 이전 결정과 달라진 점을 기록합니다.
- 변경 전(R-RQ8 8회차): 현재 버전은 픽업 시간 밖에서도 예약 확정 예약의 픽업 완료 허용 → 12회차: 실제 처리는 미정.
- 변경 후: 픽업 시작~마감(양 끝 포함) 안에서만 픽업 완료 가능. 근거는 사용자 답변과 Catalog 확정 픽업 시각(할인 상품의 픽업 시작·마감), D54 안내 문구.
- 이 질문의 ③(마감까지 찾아가지 않은 예약의 상태·환불)은 답변에서 미확정이라 RQ-18로 옮겼습니다.
반영: REQ-22, 주체와 정책 / 픽업 완료, 경계값 / 픽업 가능 시간(신규), 상태와 전이 / 예약 확정 → 픽업 완료, RQ-18 신설 (13회차, 2026-11-06)

### RQ-18. 픽업 마감까지 찾아가지 않은 결제 완료 예약은 어떻게 하나요?
대상: REQ-22
배경: RQ-17에서 픽업 가능 시간은 정해졌지만, 사용자 답변이 "픽업 마감 이후 상품을 찾아가지 않은 결제 완료 예약의 최종 상태 및 환불 처리는 아직 확정하지 않습니다"라고 해 이 질문으로 나눴습니다. 지금은 그런 예약이 예약 확정 상태로 남고, 픽업 완료도 고객 취소(취소 가능 시각 이후)도 환불 요청도 할 수 없습니다. 돈과 상태에 관한 결정이라 작성자가 정하지 않습니다.
제안: 정하지 않고 묻습니다. 정할 것: ① 최종 상태(예약 확정 그대로 / 취소 / 새 상태) ② 환불 여부와 금액 ③ 누가·언제 처리하는지(자동 또는 상점주·관리자). 사용자 답변에 따라 결정 전까지 자동 취소·자동 환불·새 예약 상태는 두지 않습니다. Catalog 담당자와 같은 답이어야 합니다.


사용자: (2026-11-10, 대화로 받은 사용자 결정, A안) 새 NO_SHOW 상태를 만들지 않음. `now > pickup_end`이면 미수령으로 판단. 미수령 예약은 매장 폐점·상점주 탈퇴를 막지 않음. 고객 탈퇴나 판매 중단 시 미수령 예약은 자동 환불·재고 복구하지 않음. 기존 예약 상태는 RESERVED로 유지. 미수령 목록 표시 방식은 이번 작업에서 제외.
반영: REQ-22, REQ-32(신규) (15회차, 2026-11-10). 코드는 PR #57(머지)
